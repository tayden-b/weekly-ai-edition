# V3: Per-page routes + OG image generation

**Wave:** 2 · **Depends on:** C2, C4

## Context

PLAN §4: each page has its own URL (`/2026-w44/6`) and OG image so a single page is shareable. DESIGN §1.5.5: OG images generated per page from the template — paper ground, masthead, page kicker, headline, 1200×630.

## Scope

- Route `/{issue}/{page}` (1-based page number) rendering that single page standalone — same content as its deck card / front-page section, on the paper ground, with prev/next page links and a link back to the full issue.
- Generated OG image per page at 1200×630: paper ground, masthead, page kicker, page headline — built from `@weekly/ui`'s `OgCard` and the DESIGN tokens (e.g. `next/og` ImageResponse or a build-time generator; record the choice).
- Correct `opengraph-image`/Twitter metadata on every route, including the issue root (OG = the Briefing card per §2.2) and per-page URLs.
- Invalid page numbers → 404 (`notFound()`).

## Out of scope

- Cover photograph art (typographic template only; T3 deferred).

## Interfaces

- Reads `Edition`/`EditionPage` from `@weekly/schema`; `OgCard` from `@weekly/ui`.

## Proof

- Every page of the fixture edition has a working `/{issue}/{n}` route + OG image; a social-preview render (or generated PNG) attached to the PR.
- `curl -I` (or metadata dump) shows correct `og:image`, `og:title`, dimensions 1200×630.

## Acceptance

- `/2026-w44/{1..11}` each render their page standalone with correct content + navigation links.
- OG image per page generated at 1200×630 matching the §1.5.5 template.
- Issue root + every page route carry correct OG/Twitter metadata.
- Out-of-range page numbers 404.
- `pnpm check` + `pnpm build` green.
