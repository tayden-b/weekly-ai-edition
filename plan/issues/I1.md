# I1: End-to-end — `pnpm edition:build --week 2026-W44` → valid edition → preview

**Wave:** 4 · **Depends on:** P1–P7, V1–V4, A1–A10

## Context

PLAN §5.2 defines the full stage chain. This is the first time the whole machine runs together: raw cache → normalized clusters → classified/extracted/drafted items → verified edition JSON → rendered preview. The fixture week 2026-W44 is the proving ground.

## Scope

- `pnpm edition:build --week <id>` CLI (root script): orchestrates ingest (from `data/raw/` cache; falls back to live adapters where cache is absent) → normalize → dedupe → classify → rank → extract → draft → verify → emit `editions/<week>.json` → schema-validate. LLM stages run through the session `llm()` seam per §8 — the CLI supports both the session hand-off format and replay.
- Emitted `editions/2026-w44.json` passes `schema:validate` + `provenance:check` cleanly.
- The edition renders on the Vercel preview in both renderers (fixture data may be extended with cached real items — document which sources actually contributed).
- CONTRIBUTING.md updated: how to run the pipeline end-to-end on fixtures/cache.

## Out of scope

- The weekly cron automation (I2); production deploy specifics (I3); design QA fixes (I4).

## Interfaces

- Every stage's in/out types from P1–P7; `editions/<week>.json` write format from C2; `data/raw` layout from P3.

## Proof

- PR shows the emitted JSON head + the validation output; preview URL renders the edition on mobile + desktop screenshots.
- Re-run on the same cache → identical edition JSON (deterministic given the same responses file).

## Acceptance

- `pnpm edition:build --week 2026-W44` runs the full chain and emits `editions/2026-w44.json`.
- Emitted edition passes schema validation and all §5.3 provenance gates.
- Preview deploy renders the edition in both renderers; screenshots attached.
- Re-running on the same inputs is deterministic.
- `pnpm check` green.
