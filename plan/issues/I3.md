# I3: Production deploy on *.vercel.app + analytics + security headers

**Wave:** 4 · **Depends on:** V4, I1

## Context

PLAN §7.6: v1 ships on `*.vercel.app` (no custom domain — needs payment). The Vercel project is already linked (root `apps/web`) from the hand-off. This item hardens the production surface.

## Scope

- Confirm/configure the production deployment: `main` merges deploy to the `*.vercel.app` production domain; the exact production URL documented in README.
- Security headers in `next.config.ts`: `X-Content-Type-Options`, `Referrer-Policy`, `X-Frame-Options`/`frame-ancestors`, `Permissions-Policy` — pick sane static-site values and document.
- Analytics: privacy-respecting and keyless — Vercel Analytics (`@vercel/analytics`) is the default choice; if it needs anything not available, document and pick the no-key alternative.
- `robots.txt` + `sitemap.xml` covering issues + archive.

## Out of scope

- Custom domain, email, MCP endpoint (post-v1 per PLAN).

## Interfaces

- Existing Vercel↔GitHub project link; no secrets (Vercel env vars are platform-side).

## Proof

- Production URL live and serving the latest edition; `curl -I` output showing the headers; robots/sitemap reachable.

## Acceptance

- Production deploy live on `*.vercel.app` serving the latest edition; URL documented.
- Security headers configured and verified on the live URL.
- Keyless analytics wired (or documented fallback).
- `robots.txt` + `sitemap.xml` served.
- `pnpm check` green.
