# T1: Agent twin — .md/.json per issue + Accept: text/markdown

**Wave:** 3 · **Depends on:** C2, V1, V2

## Context

PLAN §4: for every issue — `/{issue}.md` (YAML frontmatter + the full briefing, no nav), `/{issue}.json` (the raw edition object); `Accept: text/markdown` on any issue URL returns the `.md`. The twin is a first-class product surface — an agent must be able to consume a whole week from one URL.

## Scope

- `/{issue}.md` route: YAML frontmatter (issue id, date range, page list, source counts) + the full briefing and every page's items in clean Markdown — no nav, no chrome.
- `/{issue}.json` route: the exact edition object served `application/json`.
- Content negotiation: `Accept: text/markdown` on `/{issue}` returns the `.md` representation (middleware or route handler).
- Both twins generated from the same `editions/<week>.json` at build time — zero divergence risk.
- Back page "For agents" block links to both (wire up if V2 hasn't already).

## Out of scope

- `llms.txt`/feeds (T2); MCP endpoint (post-v1).

## Interfaces

- `Edition` from `@weekly/schema`; generated at build time with the site.

## Proof

- `curl -H 'Accept: text/markdown' /2026-w44` returns Markdown; `/{issue}.md` and `/{issue}.json` diff clean against the fixture.
- A paste of the `.md` output in the PR shows frontmatter + briefing + items, zero nav.

## Acceptance

- `/{issue}.md` serves YAML frontmatter + full briefing + all items, no nav chrome.
- `/{issue}.json` serves the exact edition object as `application/json`.
- `Accept: text/markdown` on `/{issue}` returns the Markdown twin.
- Twins are build-generated from `editions/<week>.json` — content provably identical.
- `pnpm check` + `pnpm build` green.
