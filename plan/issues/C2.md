# C2: edition.schema.json + TS types + validator + fixture issue 2026-W44

**Wave:** 1 · **Depends on:** B0

## Context

PLAN §3 (fixed template), §5.3 (provenance gates — schema is the enforcement surface), §4 (agent twin: `.json` twin is this object), and DESIGN §3 (per-page rules: max items per page, required fields). The schema is THE contract between pipeline, viewers, and CI. Everything downstream consumes it.

## Scope

- `packages/schema/edition.schema.json`: the edition object — id (`2026-w44` form), date range, pages array in fixed template order (cover, briefing, models, performance, launches, funding, deals, markets, discourse, most_covered, back_page), each item with headline, one_liner, optional take, optional number, `sources[]` (required, non-empty) where each source has `url`, `publisher`, `published_at`, `fetched_at`, `adapter`.
- Per-page `maxItems` enforced by schema where DESIGN §3 fixes them (models 6, performance 5, launches 6, funding 6, deals 4, discourse 3, most_covered 5; briefing 5–7 sentences; markets 1 chart + ≤10 tickers).
- `evidence: {source_index, quote}` required on every numeric claim on money/performance/markets pages.
- Company tag field constrained to slugs (validated against `config/companies.yaml` at verify time, not necessarily by JSON schema itself — document the boundary).
- Generated TypeScript types + a `validateEdition(json)` function exported from `@weekly/schema` (generation approach is your call — hand-written types validated by a test, or codegen; record the choice in the PR).
- `fixtures/2026-w44/` — one hand-built reference edition **using real public URLs** (real headlines/sources from that week), exercising every page type at least once. This fixture is consumed by tests, kitchen-sink, and previews.
- Replace the `schema:validate` stub: `scripts/schema-validate.mjs` (or a package bin) validates every `editions/*.json` and `fixtures/**/*.json` — fails nonzero on any violation; wired into `pnpm check`.

## Out of scope

- The pipeline itself (C5, P-items); the viewers (V-items).
- Live data — the fixture is hand-built from real public URLs, not fetched.

## Interfaces

- `@weekly/schema` exports `Edition`, `EditionPage`, `EditionItem`, `EditionSource`, `EditionWeekId`, `validateEdition`, `EDITION_SCHEMA_VERSION`.
- `RawItem` (C5) maps into `EditionItem` + `sources[]` — coordinate the field names so C5 can adopt them unchanged.
- `pnpm schema:validate` is the CI entry point.

## Proof

- `pnpm schema:validate` passes on the fixture and fails (nonzero exit, clear message) on a deliberately broken edition — demonstrate both in the PR.
- The fixture renders every template page type; a viewer can consume it unchanged (V1/V2 briefs assume it).
- Type-level test or codegen check keeps `edition.schema.json` and the TS types in sync.

## Acceptance

- `edition.schema.json` covers all 11 template pages in fixed order with DESIGN §3 max-items caps enforced.
- Every item requires `sources[]` with url/publisher/published_at/fetched_at/adapter; zero-source items fail validation.
- Numeric fields on money/performance/markets pages require `evidence {source_index, quote}`.
- Generated/hand-synced TS types + `validateEdition` exported from `@weekly/schema`; sync enforced by a test.
- `fixtures/2026-w44/` hand-built edition using real public URLs validates and covers every page type.
- `pnpm schema:validate` is a real check wired into `pnpm check`.
