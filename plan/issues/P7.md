# P7: Verify stage (PLAN §5.3) + provenance.json

**Wave:** 3 · **Depends on:** P6, C2

## Context

PLAN §5.3 — the spine of the product, CI-enforced. HANDOFF non-negotiable: never weaken these gates to get a PR green. This item turns §5.3 into the real `provenance:check` gate.

## Scope

- `packages/pipeline/src/stages/verify.ts` — deterministic checks on a candidate edition:
  1. every item has `sources[]` with url/publisher/published_at/fetched_at/adapter; zero-source items fail;
  2. every number on Money/Deals/Performance/Markets has `evidence {source_index, quote}` and `quote` is a verbatim substring of the referenced source's stored excerpt;
  3. every company tag resolves to a slug in `config/companies.yaml`;
  4. discourse items have ≥ 2 sources from ≥ 2 distinct publishers;
  5. briefing sentences carry sentence→item attribution from P6 and each sentence is supported by ≥ 1 item — the entailment judgement itself goes through the `llm()` seam (session-performed, recorded for replay per §8), while all other checks are pure code;
- `provenance.json` per edition: every adapter run, item counts, failures, cache hashes — the data the back page and `.md` twin render.
- Replace `scripts/provenance-check.mjs` stub: real implementation validating every `editions/*.json` (+ fixture) against the deterministic checks 1–4 and the presence of a valid `provenance.json`; wired into `pnpm check`.

## Out of scope

- Changing stages upstream to make this pass — if a field is missing upstream, the stage that owns it must emit it (open `plan-defect` if the boundary is ambiguous).

## Interfaces

- Consumes the full candidate `Edition` (C2) + raw manifests (P3) + companies config (C5).
- `provenance:check` is the CI entry point; keep the failure messages surgical (which item, which field, which rule).

## Proof

- Adversarial fixtures: an edition with (a) a zero-source item, (b) an evidence quote not in the excerpt, (c) an unknown company slug, (d) a single-source discourse item — each fails the gate with a clear message; the clean fixture passes.
- A sample `provenance.json` is emitted and rendered on the fixture back page data.

## Acceptance

- All four deterministic §5.3 checks implemented and enforced; briefings go through the recorded entailment seam.
- `provenance.json` per edition lists adapter runs, counts, failures, cache hashes.
- `scripts/provenance-check.mjs` is the real gate in `pnpm check` (stub removed).
- Each adversarial fixture fails loudly; clean fixture passes.
- `pnpm check` green.
