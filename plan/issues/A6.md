# A6: Adapter — Product Hunt + GitHub Releases + HF Hub

**Wave:** 2 · **Depends on:** C5

## Context

PLAN §5.1: Launches (Product Hunt) and Models & Releases (GitHub Releases API for flagship OSS — vLLM, llama.cpp, Ollama, LangChain, etc.; Hugging Face Hub API for new model repos from the lab orgs). PH needs a free token — see Constraints.

## Scope

- Three adapter files: `product-hunt.ts`, `github-releases.ts`, `hf-hub.ts` (one file per adapter per §5.1 rules), each implementing the C5 interface.
- GitHub Releases: release events for a config'd repo list (flagship OSS list in `config/sources.yaml`); tag name as `source_ids`.
- HF Hub: new models from the lab orgs (org list in config) sorted by createdAt in window; model id as `source_ids`.
- Product Hunt: GraphQL API — **no secrets exist and none may be added** (HANDOFF non-negotiable): implement the adapter, but gate it behind `enabled: false` in `config/sources.yaml` with a licence note that it activates only if a free PH token is ever provided via the environment (document `PRODUCT_HUNT_TOKEN` lookup, never committed). If no token, the adapter health-checks as disabled — never fails a run.
- Licence notes; fixtures + harness tests for all three (PH fixture simulates response shape).

## Out of scope

- Curating which OSS repos count as "flagship" beyond a justified seed list (document picks).

## Interfaces

- C5 `RawItem`; `config/sources.yaml` incl. per-repo/per-org entries.

## Proof

- GitHub + HF adapters: fixture replay + live smoke run output in PR.
- PH adapter: fixture replay + documented disabled-by-default behaviour (health() → skipped).

## Acceptance

- All three adapters implement the C5 interface and are registered in config.
- Flagship OSS repo list + lab org list live in config, not code.
- PH adapter is disabled without a token and never breaks the run; no secret is committed or required.
- Fixtures + deterministic tests per adapter.
- `pnpm check` green.
