# A1: Adapter — lab blogs RSS/Atom

**Wave:** 2 · **Depends on:** C5

## Context

PLAN §5.1, Models & Releases row: lab blogs via RSS/Atom (or HTML sitemaps where no feed exists) — OpenAI, Anthropic, Google DeepMind, Google AI, Meta AI, Mistral, xAI, Microsoft Research, Amazon Science, Moonshot/Kimi, DeepSeek, Alibaba Qwen, Hugging Face blog. Primary source for the Models page.

## Scope

- `packages/pipeline/src/sources/lab-blogs.ts` implementing the C5 adapter interface (`fetch(window) → RawItem[]`, `health()`).
- One feed config per lab in `config/sources.yaml` (id, feed URL or sitemap URL, licence note, rate limit). Where a lab has no feed, record the sitemap/scrape decision in the licence note; headline+link only.
- `LICENSE.md`/licence note for the adapter covering ToS posture per §5.1 rules.
- Recorded fixture `__fixtures__/lab-blogs.json` (a slice of real feed XML/JSON per source, committed) + deterministic tests via the C5 harness.

## Out of scope

- Classification/ranking (P-items); storing more than headline, URL, timestamps, ≤300-char excerpt, ids.

## Interfaces

- C5 `RawItem` contract; `config/sources.yaml` registry; project UA string.

## Proof

- Harness replay of the fixture yields ≥ 1 valid `RawItem` per enabled lab feed.
- `health()` reports per-source ok/fail without throwing.
- Live `fetch` smoke run output pasted in PR (a real fetch during the session, not in tests).

## Acceptance

- Adapter implements `fetch(window)`/`health()` per the C5 interface.
- Every lab in the §5.1 row represented in `config/sources.yaml` (feed or documented sitemap fallback).
- Licence note covers terms, rate limits, and exactly what we store per lab.
- Recorded fixture + deterministic harness test, no network in tests.
- Stores headline, canonical URL, publisher, published_at, fetched_at, ≤300-char excerpt, source ids — never bodies.
- Adapter failure degrades the page, never the run.
- `pnpm check` green.
