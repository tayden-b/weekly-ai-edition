# B0: Bootstrap — repo plumbing, orchestration, and the full issue set

**Wave:** 0 · **Depends on:** — (first item)

## Context

Governed by PLAN.md §5 (architecture), §7.1–7.4 (delegation protocol, repo-as-state-machine, waves) and HANDOFF.md (non-negotiables). This is the item that makes the repository self-driving: every later session runs unattended against the scaffolding, the DAG, and the dispatch workflow created here.

## Scope

- pnpm-workspace monorepo skeleton, TypeScript strict, Node 22: `apps/web` (Next.js App Router placeholder page rendering "The Weekly AI Edition" with the DESIGN.md paper/ink tokens inline), `packages/schema`, `packages/ui`, `packages/pipeline` (each with `package.json`, `src/index.ts`, a passing placeholder test).
- Root scripts: `pnpm check` (typecheck + lint + test + `schema:validate` + `provenance:check` + `dag:validate`), `pnpm dev`, `pnpm build`. `schema:validate` / `provenance:check` are exit-0 stubs until C2/P7 land.
- `.github/workflows/ci.yml` running `pnpm check` on PRs and `main`; job name exactly `ci`.
- `.github/workflows/dispatch.yml` + `scripts/dispatch.mjs` (no external deps): on `pull_request:closed`, `issues:closed`, `workflow_dispatch`, hourly cron — read `plan/dag.yaml`, promote `status:blocked` → `devin:ready` when all `depends_on` issues are closed; when every dag item is closed and no `v1-complete` issue exists, create it (labels `devin:ready`, `wave:5`, body = S1 brief).
- `plan/dag.yaml` (every §7.4 item) + `scripts/validate-dag.mjs` in `pnpm check` + `plan/issues/<id>.md` briefs.
- One GitHub issue per dag item (`<id>: <title>`, body = brief + acceptance, labels `wave:N` + `status:blocked`); issue numbers written back into `dag.yaml`; C1–C5 labelled `devin:ready` when done.
- Branch protection on `main` via `gh api`: PRs required, required checks `ci` + Devin Review check, auto-merge allowed, squash only, delete branch on merge, no human approvals. Repository auto-merge enabled.
- `CONTRIBUTING.md` for agents; `docs/adr/0001` (monorepo + git-as-CMS) and `0002` (no external LLM APIs).

## Out of scope

- Any product code (viewers, adapters, pipeline stages) — those are the wave items this item creates.
- Vercel project creation (already linked by hand-off; root `apps/web`).
- Devin Review installation (org-level; this item only adds the required check name to branch protection once it has run).

## Interfaces

- `plan/dag.yaml` schema consumed by `scripts/dispatch.mjs` and `scripts/validate-dag.mjs`: `{id, title, wave, issue, depends_on, brief, acceptance, status?}`; `status: deferred` items are never promoted and not required for completion.
- `pnpm check` is the single gate every later PR must pass.

## Proof

- `pnpm install && pnpm check` passes on a clean clone.
- `node scripts/validate-dag.mjs` output lists all items acyclic with briefs present.
- `gh api repos/{owner}/{repo}/branches/main/protection` shows required checks, auto-merge settings.
- `gh workflow run dispatch.yml` completes green with no label changes.

## Acceptance

- `pnpm install && pnpm check` passes on a clean clone.
- CI job `ci` is green on the PR; Vercel preview deploys `apps/web`.
- Branch protection active with auto-merge; the B0 PR merges via auto-merge once checks pass.
- `plan/dag.yaml` validates (`scripts/validate-dag.mjs`: unique ids, acyclic, deps resolve, briefs exist) as part of `pnpm check`.
- All dag items exist as issues with correct labels; C1–C5 are `devin:ready`.
- `workflow_dispatch` of `dispatch.yml` runs green and changes nothing.
