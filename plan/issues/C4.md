# C4: packages/ui tokens + primitives + /kitchen-sink

**Wave:** 1 · **Depends on:** B0

## Context

DESIGN.md is verbatim law: §1 tokens, §1.3 space/grid/rules, §1.4 motion, §2 the two renderers' anatomy, §4 the component list (18 primitives), §5 a11y/perf budgets, §6 don'ts. HANDOFF: tokens live in `packages/ui`; nobody hardcodes a colour or font size.

## Scope

- `packages/ui` exports the full token set from DESIGN §1: colour (light + dark), type roles + scale (`--t-xs` … `--t-3xl` with clamp ranges), space scale (4·8·12·16·24·32·48·64·96·128), motion durations/easings — as TypeScript constants AND a `tokens.css` emitting the CSS custom properties (both schemes via `prefers-color-scheme`).
- Font loading strategy: Inter Tight / Inter / Geist Mono, self-hosted subsets, `font-display: swap` (DESIGN §7.3); wire the `<link>`/font-face plumbing in `apps/web`.
- All 18 primitives from DESIGN §4 — `Masthead`, `IssueMeta`, `Kicker`, `SectionHead`, `Item`, `ItemList`, `Rule`, `Pill`, `MonoTable`, `TrendDelta`, `ProgressSegments`, `DeckCard`, `Deck`, `FrontPage`, `CoverImage`, `LineChart`, `AgentAccess`, `OgCard` — implemented to the spec (hairline rules not boxes, zero radius except pills/images, no shadows, accent at most once per viewport).
- `/kitchen-sink` route in `apps/web` rendering the C2 fixture issue via the primitives in both light and dark, every component exercised.
- Refactor `apps/web` placeholder page to consume tokens from `@weekly/ui` (no inline hex).

## Out of scope

- The actual deck/front-page page assembly logic (V1/V2 build pages from primitives).
- Storybook — the kitchen-sink route is the story surface (PLAN has no Storybook dep).

## Interfaces

- `@weekly/ui` is the ONLY source of visual constants; `apps/web` and future packages import from it.
- Components take plain props derived from the C2 edition types — no network, no fetching inside primitives.
- `tokens.css` contract: `--paper`, `--ink`, `--accent`, `--t-*`, `--space-*` etc. named exactly as DESIGN.md writes them.
