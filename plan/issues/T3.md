# T3: Cover-image generation step (DEFERRED — post-v1)

**Wave:** 3 · **Depends on:** C3, P7 · **Status: deferred**

## Context

DESIGN §1.5.2: the cover is one full-bleed generated image per issue — muted abstract/material imagery, never people or products — stored in `editions/<week>/cover.jpg` (2000×2500 portrait + 2400×1350 landscape crop), ≤180KB AVIF for serving. DESIGN §7.4: the generation prompt + style constraints live in STYLE.md (C3); the pipeline produces a candidate, the human approves it in the issue PR. **Deferred for v1** — v1 ships typographic covers; this item is post-v1 scope, recorded here so the design intent is not lost.

## Scope (when picked up post-v1)

- A pipeline step that produces a cover candidate per the STYLE.md prompt constraints and writes `editions/<week>/cover.jpg` + landscape crop.
- `CoverImage` consumes the files; fallback to typographic cover when absent.
- Human-approval step documented (generation happens in the weekly PR review per §7.4).

## Out of scope

- Everything for v1 — this issue is intentionally `status: deferred` in `plan/dag.yaml`; dispatch never promotes it and it does not block `v1-complete`.

## Interfaces

- STYLE.md cover constraints (C3); pipeline emit stage (P7); `CoverImage` (C4/V1).

## Proof (post-v1)

- A generated cover + crop attached to a weekly PR, visually matching §1.5.2 constraints.

## Acceptance

- Generation prompt + constraints sourced from STYLE.md (single source of truth).
- `editions/<week>/cover.jpg` 2000×2500 + 2400×1350 crop produced by the pipeline.
- Imagery is muted abstract/material — no people, products, or article photos.
- Served asset ≤ 180KB AVIF.
- Typographic fallback remains when no cover exists.
