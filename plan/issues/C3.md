# C3: STYLE.md + drafting rubric + 50-item labelled classification set

**Wave:** 1 · **Depends on:** B0

## Context

PLAN §5.2 (classify → draft stages), §8 (LLM work performed by the Devin session following versioned prompts), DESIGN §7.4 (cover generation prompt + style constraints live in STYLE.md), DESIGN §3 (per-page framing rules, e.g. discourse framed as a question). STYLE.md is the editorial voice contract; the rubric and labelled set are the objective functions P4/P6 are measured against.

## Scope

- `STYLE.md`: voice (calm, precise, zero hype), one-liner format (what it is + why it matters, ≤ ~140 chars), Briefing rules (5–7 sentences, no links, synthesis not summary), take usage (italic, after em-dash, rare), discourse framing (a question, both sides linked), per-page house rules from DESIGN §3 (funding format `**Company** raised **$Xm** Series B led by Lead`, version numbers in mono, etc.), banned patterns (hype words, engagement bait), and the cover-generation prompt + constraints per DESIGN §7.4/§1.5 (muted abstract, no people/products).
- `packages/pipeline/prompts/` seeded with the classify + draft prompt templates that P4/P6 will fill/execute (versioned in git per §8).
- Drafting rubric (`STYLE.md` section or `plan/rubric.md`): mechanically checkable pass/fail criteria — e.g. every claim traces to an item, no unsupported adjectives, Briefing is 5–7 sentences, no links in Briefing.
- Labelled classification set: ≥ 50 items covering every taxonomy page type plus `unsorted`, stored under `packages/pipeline/testdata/` (or `fixtures/`), each with real public URL + expected page label + expected company tags. Format must be loadable by P4's accuracy harness.

## Out of scope

- The classifier/drafter implementations (P4/P6) — this item defines their spec and test data.
- The taxonomy itself beyond what PLAN/DESIGN imply — the page types ARE the taxonomy; document that.

## Interfaces

- `prompts/` directory layout consumed by P4/P6 (define `classify.prompt.md`, `draft.prompt.md` skeletons).
- Labelled-set file format documented in the file or a colocated README so P4 can build its accuracy harness without guessing.

## Proof

- Every taxonomy category appears ≥ 3× in the labelled set; `unsorted` examples included.
- Rubric items are binary-checkable (a reviewer can mark pass/fail without taste judgments).
- STYLE.md alone is sufficient for P6 to draft a conforming Briefing — verified by applying it to 2–3 fixture items in the PR description.

## Acceptance

- `STYLE.md` covers voice, one-liners, Briefing, takes, discourse framing, per-page rules, banned patterns, and the cover prompt constraints.
- Drafting rubric exists and every criterion is mechanically checkable.
- ≥ 50 labelled items with real public URLs covering every page type + `unsorted`, each with expected page + company tags.
- `packages/pipeline/prompts/` contains versioned classify + draft prompt skeletons.
- `pnpm check` green.
