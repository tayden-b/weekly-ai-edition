# I4: Design QA pass — every page, both renderers, vs DESIGN.md

**Wave:** 4 · **Depends on:** V1, V2, V3, V4

## Context

DESIGN.md is verbatim law; §7.6 admits nobody looks at the design until v1 — THIS pass is the mitigation (catch drift from the spec). §6 don'ts are as binding as the dos.

## Scope

- Audit every route — `/{issue}` (deck @390×844 + front page @1440×900), every `/{issue}/{n}` page, `/issues`, `/brand`, `/`, twins sanity — against DESIGN.md section by section.
- Checklist driven: tokens used correctly (accent ≤1 per viewport, up/down only next to numbers), type scale, rules-not-boxes, radii (0 except pills/images), motion spec, density, don'ts (no gradients/shadows/emoji/decorative icons).
- Fix drift in this PR; where a fix is genuinely out of scope or ambiguous, file a `plan-defect` issue and continue.
- Produce a written QA table (page × check × pass/fail) attached to the PR + full-page screenshots both viewports, light + dark.

## Out of scope

- Redesign; anything not in DESIGN.md (taste calls deferred to post-v1 per §7.6).

## Interfaces

- DESIGN.md as the oracle; `@weekly/ui` tokens (fixes should change tokens/primitives, not patch pages).

## Proof

- QA checklist table + screenshot set on the PR; each fixed drift noted with before/after.

## Acceptance

- Every page audited at 390×844 and 1440×900, light + dark, against DESIGN.md.
- All §6 don'ts verified absent; token/scale/motion rules verified present.
- Drift fixed or filed as `plan-defect` issues with the narrowest reading applied.
- QA table + screenshots attached to the PR.
- `pnpm check` green.
