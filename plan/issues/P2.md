# P2: Pipeline — rank stage

**Wave:** 2 · **Depends on:** P1

## Context

PLAN §5.2: `rank` — deterministic: source count × publisher weight × recency × HN/Reddit engagement. This ordering decides what surfaces on each page and what leads the Briefing, so it must be explainable and reproducible.

## Scope

- `packages/pipeline/src/stages/rank.ts`: pure scoring function over P1's clusters — `score = f(source_count, publisher_weight, recency, engagement)` with each factor's formula documented in the file header (normalize factors to comparable ranges; make the composition auditable).
- Publisher weights sourced from `config/sources.yaml` (add a `weight` field if absent) — never hardcoded.
- Engagement from captured HN points/comments + Reddit score/comments (A2/A9 fields); absent engagement = neutral factor, not zero.
- Deterministic tie-breaking (e.g. newest published_at, then canonical id) — no wall-clock dependence.
- Tests: known fixture inputs → expected ordering; a score breakdown is emitted per item (debuggability for reviewers).

## Out of scope

- Per-page top-N selection (emit stage); LLM reranking (none — deterministic by design).

## Interfaces

- Consumes P1's cluster type; outputs `RankedCluster` with `score` + `score_breakdown`.

## Proof

- Fixture test: multi-source + fresh + high-engagement item outranks single-source stale item; breakdown printed in PR.

## Acceptance

- Score formula = source count × publisher weight × recency × engagement, each factor documented + normalized.
- Publisher weights come from config, not code.
- Missing engagement is neutral; ties break deterministically.
- Per-item score breakdown emitted for auditability.
- `pnpm check` green.
