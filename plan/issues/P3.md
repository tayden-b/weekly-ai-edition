# P3: Daily ingest cache workflow

**Wave:** 2 · **Depends on:** A1, A2, A3, P1

## Context

PLAN §5.2: `ingest` runs all adapters in parallel, caching raw to `data/raw/<date>/`; daily 06:00 ET ingest keeps the raw cache warm and feeds the agent surface later. Adapter failure degrades the page, never the run (§5.1).

## Scope

- `packages/pipeline` ingest orchestrator: run every adapter marked `enabled` in `config/sources.yaml` in parallel, isolate failures (catch per adapter, record `{adapter, ok, count, error?}`), write raw output to `data/raw/<YYYY-MM-DD>/<adapter>.json`.
- `.github/workflows/ingest-daily.yml`: cron `0 11 * * *` (06:00 ET ≈ 11:00 UTC; comment the TZ assumption), runs ingest, commits `data/raw/` back to `main` via GITHUB_TOKEN (git-as-CMS: raw cache lives in git — if you judge that wrong, open a `plan-defect` and use Actions artifacts + document the decision).
- Idempotent re-runs for the same date (same inputs → same cache file names/content shape).
- `provenance` record per run: per-adapter item counts + failures appended to the run manifest (`data/raw/<date>/manifest.json`).

## Out of scope

- The weekly full-build workflow (I2); classification of cached items (P4).

## Interfaces

- C5 adapter registry + interface; `data/raw/` layout documented in CONTRIBUTING/README for I1's cache-driven build.

## Proof

- A workflow_dispatch run produces `data/raw/<date>/` with per-adapter files + manifest; link the run in the PR.
- Re-running is a no-diff (idempotent) or produces only expected new items.

## Acceptance

- Daily 06:00 ET workflow runs all enabled adapters in parallel and commits `data/raw/<date>/` + `manifest.json`.
- Any single adapter failure is caught, logged to the manifest, and never fails the run.
- Cache layout + re-run semantics documented.
- `pnpm check` green.
